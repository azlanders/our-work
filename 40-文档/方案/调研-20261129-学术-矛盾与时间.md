## 1. 结论先行

1. **旧值问题不是“标签不够”，是“读路径必须执行”。** Revoked but Still Authoritative 测了 5 个主流记忆系统：没有一个在默认检索时执行撤销。Graphiti 把已撤销记录排在第 1 位，代理在 44.2% 的试验里执行了危险动作；只加 prompt 警告只降到 38.4%，只加输出过滤降到 19.0%，读路径过滤是 0/1,620。mnemonic 在这一项上其实已经比被审计的系统靠前：`lib/recall.js:search` 默认会把旧值命中重定向到 `resolveCurrent` 的当前值（L302），画像和未了事也跳过 `supersededBy`。真正剩下的风险是 `wantsOld` 历史路径和“用户改口”路径，不是主路径完全没做。

2. **语义相似度判不了矛盾，必须用结构化的 (主体, 关系) 作废。** MemStrata 在标定数据上测到：余弦相似度区分“被反驳的旧事实”和“换说法的重复事实”的 AUROC 只有 **0.59**（接近随机），而且矛盾事实平均比复述更相似（0.812 vs 0.800）。改成确定性的三元组作废后，演化类基准从 RAG 的 0.20–0.47 提到 **0.95–1.00**，被迫作答时旧值率从 **15–40% 降到约 0%**。这直接支持 mnemonic 继续走 `supersede.js` 的链，而不是加“矛盾检测阈值”。

3. **时间题要把计算移出模型，但只值得在强模型上做。** TReMu 用“时间线摘要 + 让模型生成 Python 做日期运算”把 GPT-4o 从 29.83 提到 **77.67**，但同一个框架在 GPT-3.5 上只有 **33.67**，Temporal Interval 子项 **22.22**，反而低于标准提示的 23.83。结论不是“上代码执行”，而是“日期换算必须在注入层做完，模型只抄”；小模型上再叠一套推理链是负期望。

4. **多轮纠错有稳定的“对话税”，不能指望模型自己记住“不是这个”。** 17 个模型、3 个临床基准上，把同一组选项拆成多轮顺序呈现，端到端准确率和“对错误建议的弃权”平均最多掉 **30%**，部分模型到 **65%**；从“原本弃权”转为接受错误建议和正确建议的比率接近，最高 **50%**（blind switching）。纠错必须落成一次显式的状态变更（新记录 + 旧记录作废），而不是在下一轮 prompt 里补一句“她刚说不是这个”。

5. **引用能提升可验证性，但不保证正确。** CiteGuard-RAG 在受控住房法数据上报告 98.3% grounded-answer、98.3% citation validity；一旦换域，证据利用、span 对齐和拒答校准都变差。CiteShade 更直接：攻击者控制一个来源，就能把多跳 QA 的错误答案率从 **0.01 提到 0.68**，而且模型仍把答案归因给一个不支持它的可信来源。引用只能当“事后可检查的形态”，不能当“答案正确”的证明。

## 2. 来源卡片

### 2.1 Supersede：有界记忆的更新缺口，不是理解力问题

- **来源**：*Supersede: Diagnosing and Training the Memory-Update Gap in LLM Agents*，arXiv:2606.27472，2026-06。级别 **B**（有公开 RL 环境，单次训练跑）。
- **机制**：在 LongMemEval 的 knowledge-update 子集上，把“全上下文”换成“有界、自维护的记忆”，测同一模型是否还用当前值；再做一个以“答当前值加分、答旧值扣分”为奖励的 GRPO 环境。
- **量化（作者报告）**：
  - 全上下文 **92%** → 有界记忆 **77%**（gpt-5.4，配对 McNemar p<0.005）；全上下文准确率在 92% 附近饱和。
  - 对话长度扩到 24 倍，准确率从 **68% 掉到 28%**；按比例给更多记忆预算，**28% → 28%**（n=25），没有可检测的恢复。
  - Qwen2.5-3B 在这个环境上 GRPO 微调，held-out supersession 从 **9.0% 到 16.7%**（单次运行），仍远低于可用水平。
- **适用**：事实会随会话变化、且“当前值”可判定的场景；说明更新能力是独立能力，模型更强不等于更好。
- **失败条件**：奖励是“当前值/旧值”的二元信号，需要标注；小模型训练后仍只有 16.7%，不能拿它当通用解。作者也只做了单次训练运行。
- **对 mnemonic 的含义**：不要用“加大注入预算/换更强模型”来解旧值题；要把“当前值优先”做成读路径的硬约束。`card.js` 注释里已经引用过这篇的 92→77，但生产行为还没完全按这个结论收口。

### 2.2 MemStrata：余弦相似度分不清“矛盾”和“复述”

- **来源**：*Temporal Validity in Retrieval Memory: Eliminating Stale-Fact Errors for AI Agents over Evolving Knowledge*，arXiv:2606.26511，2026-06。级别 **B**（本地 7B、六个基准、有 harness；未同行评审）。
- **机制**：事实仍按 RAG 方式存；当新断言与旧值的 `(subject, relation, object)` 冲突时，用确定性作废规则把旧值退休到双时态账本；读路径不跑 LLM、不设相似度阈值。历史仍可查，但默认检索只返回当前值。
- **量化（作者报告）**：
  - 标定集上 cosine 区分 contradicted vs duplicate 的 **AUROC 0.59**；矛盾事实对原事实的平均 cosine **0.8119**，复述 **0.800**；任何 duplicate 阈值能到的最高 precision 只有 **0.667**，安全自动规则需要的 0.95 够不到。
  - 静态基准与 RAG 打平：domain **0.82 vs 0.86**，LoCoMo **0.30 vs 0.30**；激进压缩消融掉到 **0.62 / 0.13**（说明“压缩”本身有代价）。
  - 演化基准 **0.95–1.00**，RAG **0.20–0.47**；被迫作答时旧值率 RAG **0.15–0.40**（code_mutation 0.40、config 0.35、dependency 0.15、api 0.35），MemStrata **0.00–0.03**。
  - 读路径延迟 **约 2.1s**（embedding 下限），LLM rerank/verify 基线 **16–18s**。
- **适用**：事实可以被键化成三元组、冲突是显式值替换（改配置、改 API、改依赖、改地址/称呼）。
- **失败条件**：自由聊天里的隐含否定、讽刺、条件句、同一主体多关系并存，未必能键化成单一 `(s,r,o)`；论文的六个基准都是“值替换”型，不是开放闲聊。静态 domain 还掉了 4 个点，说明作废层不是零成本。
- **对 mnemonic 的含义**：`profile.js:stableAttrOf` 已经在做槽位；`supersede.js:resolveCurrent` 已经在走链。缺的是“同一槽位出现两个活值”时用链/最新值定序，而不是让模型看两条自己挑。

### 2.3 Revoked but Still Authoritative：软撤销默认不执行

- **来源**：*Revoked but Still Authoritative: An Empirical Study of Revocation Enforcement in Agent-Memory Systems*，arXiv:2609.08258，2026-09。级别 **B**（5 个系统 × 9 场景 × 9 模型，代码开源；作者是安全团队，场景是策略/权限）。
- **机制**：给每个记忆系统写入一条“已撤销的策略”和它的替代策略，用普通问题检索，看撤销记录是否仍被返回、代理是否据此执行不安全动作；再比较 6 种防御条件（无防御、store filter、prompt hardening、output filter、两者组合等）。
- **量化（作者报告）**：
  - 5 个系统没有一个在默认检索时执行撤销；失败分三类：撤销根本没记录（cognee/langmem/mem0 间接写入）、记录了但不把状态暴露给调用方（Zep）、记录了也暴露了但检索不执行（Graphiti 默认、mem0 开 expiry-flag）。
  - Graphiti：撤销记录 **81/81** 都被返回且排第 1；不安全动作 **44.2%（358/810）**。mem0(exp.)：**42.1%（341/810）**。两者合计 **43.1%（699/1,620）**。
  - 防御：store-level filter **0/1,620**；只加 prompt hardening 降到 **38.4% / 36.0%**；只加 output filter 降到 **19.0% / 17.2%**；filter + prompt 组合 **0.0%**。
  - 每场景不安全率 0.0%–94.4%，每模型 15.0%–60.0%；说明“模型更强”不解决。
- **适用**：任何“保留历史、标记作废、但默认检索仍可能返回”的记忆系统——mnemonic 正是这种结构。
- **失败条件**：场景是策略/权限的二元动作，不是开放问答；store filter 需要读路径能看见状态；如果系统把状态藏起来，应用层无法补救。
- **对 mnemonic 的含义**：`search` 的默认路径已经是“读路径执行”（旧值命中先 `resolveCurrent`，拿不到当前值就不返回），方向与这篇的结论一致；需要守住的是不要在 `wantsOld` 或纠错场景退回“只把状态写给模型看”。按这篇的数字，标签最多把 44% 降到 38%，读路径过滤才是 0%。

### 2.4 TOKI：把矛盾消解当写时并发控制

- **来源**：*TOKI: A Bitemporal Operator Algebra for Contradiction Resolution in LLM-Agent Persistent Memory*，arXiv:2606.06240，2026-06。级别 **B**（形式化 + 8 系统审计；跨系统比较作者自己说 underpowered）。
- **机制**：把生产里的四种消解策略（last-writer-wins、evidence-weighted merge、await-confirmation、per-rule policy）统一成双时态算子族，每个算子声明隔离级别前提；赢家写当前行，输家写审计行；LLM judge 留在写路径时，必须 keyed logging 才能 replay。
- **量化（作者报告）**：8 个系统里，所有把 LM judge 放在写路径的基线至少中一种写时异常（replay inconsistency、belief-drift skew、audit erasure）；TOKI 三种都排除。自然负载切片上 audit-row 防御让 LoCoMo 变动 **+0.86**；消融 typed memory layer 在 1,444 道可答 LoCoMo 题上掉 **0.49**。**单位原文没写清，跨系统比较作者明确说 underpowered，只能当线索。**
- **适用**：写入频繁、需要审计和 point-in-time 查询的持久记忆；尤其是“谁覆盖了谁”必须可回放。
- **失败条件**：形式化保证依赖关系模型和调度假设；真实聊天里“同一主体多值并存”未必是矛盾，强行 last-writer-wins 会误杀。作者没有声称优于外部系统。
- **对 mnemonic 的含义**：`index.js` 写入时已经在设 `old.supersededBy = rec.id`，方向对；但“await-confirmation”式的不作废会留下两个活值。应明确：同一槽位的新值默认作废旧值，旧值只进审计/历史查询，不参与默认召回。

### 2.5 HiCoMER：有效性感知检索，而不是“相关就取”

- **来源**：*Not All Memories Are Equal: Hierarchical Collaborative Memory for Validity-Aware Retrieval in LLM Agents*，arXiv:2609.30289，2026-09。级别 **B**（两个自建数据集，Llama-3.1-8B / Qwen2.5-3B）。
- **机制**：团队记忆和个人记忆分层；先用 Hierarchical Memory Conflict Updater 维护“当前有效”，再用 Validity-Aware Retriever 只从有效记忆里取，最后 grounded answer generator。
- **量化（作者报告，ALI 数据集，Llama-3.1-8B）**：
  - Outdated Retrieval Rate@5（越低越好）：Mem0 **28.63** → HiCoMER **14.18**；Flat RAG 45.83。
  - Current Retention Rate@5（越高越好）：Mem0 **70.84** → HiCoMER **84.87**。
  - Decision F1：57.36 → **64.61**；ROUGE-L：47.48 → **52.93**；NDCG@10：59.27 → **68.74**。
  - Qwen2.5-3B 上也保持增益，作者归因于框架而非 backbone 规模。
- **适用**：多代理/团队共享记忆，存在“团队共识 vs 个人旧观察”的层级冲突。
- **失败条件**：需要训练 updater 和 retriever（有标注的维护实例 + pairwise ranking），不是零样本；两个数据集是作者自建，外部效度未知；聊天场景没有“团队/个人”层级。
- **对 mnemonic 的含义**：借“先维护有效性、再检索”，不借训练管线。mnemonic 的“有效性”就是 `supersededBy` + `muted`，读路径应只取有效记录；层级可以映射成“画像/约定（稳定）> 原话（证据）”。

### 2.6 RegimeCouncil：冲突治理的“局部 vs 全局”作用域

- **来源**：*RegimeCouncil: Paired-Evidence Routing For Memory Conflict Governance In LLM Agents*，arXiv:2611.22113，2026-11。级别 **B**（有理论 + 30 个 held-out 设置；奖励信号是延迟反馈）。
- **机制**：不重训 LLM；每个记忆辅助回答与“无记忆锚点”做配对比较，Local Advisor 只跟踪被问的那条事实，Global Advisor 汇总全库近期结果；Meta Governor 默认 Local，只有当全局池化有严格正收益时才切 Global。
- **量化（作者报告）**：LongMemEval streams、TempLAMA/TAQA 历史漂移、延迟 τ∈[1,96]、稀疏/bandit 反馈，Qwen3-30B-A3B 与 GPT-4o；在全部 30 个 held-out 设置上优于更好的固定作用域，**disagreement episodes 上 +5.2–7.3 点**；clustered shifts 下比单独 cold-start fallback **+27.9 点**；微秒级开销。
- **适用**：有“动作→延迟结果”的反馈闭环（工具调用、推荐、执行策略），且冲突是“这条旧了”还是“整库都旧了”需要在线判断。
- **失败条件**：聊天里没有可靠的动作结果信号，无法做 paired comparison / IPS；增益只在 disagreement episodes 上报告，不是整体准确率；30 个设置是作者自己的流式模拟。
- **对 mnemonic 的含义**：不要引入 bandit。可借的是“默认只处理被问的那条（local），不要把一条旧值上升成全局规则”；对应 `index.js` 的 slot 冲突提示应限制在命中的槽位，不要输出“记忆里说法不一致”这种全局告警。

### 2.7 双时态图存储：时间旅行查询会伤时间推理

- **来源**：*A Graph-Native Bitemporal Memory Store for Conversational AI Agents*，arXiv:2607.26520，2026-07。级别 **B**（60 题抽样，作者自测）。
- **机制**：Neo4j 属性图 + HNSW；每个记忆是不可变 identity 节点，内容节点带 valid time / transaction time 两个半开区间；写时用 1024 维余弦维护语义边；支持 point-in-time 检索，不物理覆盖历史。
- **量化（作者报告）**：LongMemEval 抽 60 题；current-state 语义检索 **46.7% R@10**，knowledge-update 上 **80%**；time-travel 路径 knowledge-update 仍 **80%**，但 temporal-reasoning 从 **50% 掉到 37.5%**（post-filter dilution）。
- **适用**：需要“当时知道什么”和“世界上当时是什么”分开的审计场景。
- **失败条件**：时间旅行路径不是免费增益；对“相对日期/时序”反而更差。60 题样本很小，不能当稳定结论。
- **对 mnemonic 的含义**：不要加“按时间点回放”的默认路径；时间题要的是**当前视角下的绝对日期 + 距今**，不是把模型送回旧版本。

### 2.8 TReMu：时间线摘要 + 代码执行，强模型有效、弱模型反噬

- **来源**：*TReMu: Towards Neuro-Symbolic Temporal Reasoning for LLM-Agents with Memory in Multi-Session Dialogues*，arXiv:2502.01630，2025-02。级别 **B**（LoCoMo 增强出 600 道多选 + 112 道不可答；AWS 作者）。
- **机制**：每个 session 生成时间线摘要，给事件推断日期，做成可检索记忆；回答时让 LLM 生成 Python 代码做时间计算并选答案。
- **量化（作者报告，GPT-4o）**：标准提示 **29.83** → CoT **61.67** → Timeline+CoT **71.50** → TReMu **77.67**；Temporal Interval 子项 **68.38**；不可答 F1 **64.42**。
  - GPT-3.5：23.83 → 25.83 → 30.67 → **33.67**；Temporal Interval **22.22**，低于标准提示 23.83。
- **适用**：多 session、事件有可推断日期、模型能稳定生成/执行代码；强模型上收益巨大。
- **失败条件**：弱模型上代码生成/日期推断错误会级联；Temporal Interval 这种跨 session 依赖最容易崩；需要额外的摘要和代码执行成本。
- **对 mnemonic 的含义**：不要在聊天链路里跑 Python；把“日期推断 + 差值”放到 `dates.js` / `card.js` 的渲染层，模型只抄。弱模型（qwen-flash 级）不要指望 CoT 修日期。

### 2.9 LongMemEval：五种长期记忆能力与三条可复现优化

- **来源**：*LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory*，ICLR 2025，arXiv:2410.10813。级别 **A**（数据/代码公开）。
- **机制**：500 道题，五种能力：信息抽取、多 session 推理、时间推理、知识更新、弃权；把记忆设计拆成 indexing / retrieval / reading 三段。
- **量化（作者报告）**：
  - 商用助手和长上下文 LLM 在持续交互上 **30%–60%** 的性能下降。
  - fact-augmented key expansion：recall@k **+9.4%**，下游 QA **+5.4%**。
  - time-aware indexing + query expansion：时间推理 recall **+6.8%–11.3%**（强 LLM 做 query expansion 时）。
  - 即使完美 recall，reading 仍难：Chain-of-Note + 结构化数据格式在三个 LLM 上最多 **+10 绝对点**。
- **适用**：长期对话记忆的通用评测；三条优化都是“注入/索引”层，不需要训练。
- **失败条件**：500 题是英文个人助手场景；时间优化的增益依赖 query expansion 质量；CoN 的 +10 是“reading 阶段”的上限，不是端到端必然。
- **对 mnemonic 的含义**：`RECALL_RULES` 第 6 条的逐句 `[M#]` 与 CoN 同向；时间题应单独做 query expansion + 小池子，而不是所有题共用 900 字大池。

### 2.10 Memora：知识变异压力下的“忘记感知”指标

- **来源**：*From Recall to Forgetting: Benchmarking Long-Term Memory for Personalized Agents*，arXiv:2604.20006，2026-04。级别 **B**（新基准 + 人工校验；作者自建生成管线）。
- **机制**：周/月/季跨度对话，三类任务（remembering / reasoning / recommending）；引入 Forgetting-Aware Memory Accuracy (FAMA)，对“用了已失效记忆”扣分，即使最终答案碰巧正确。
- **量化（作者报告）**：
  - 记忆压力：Memora quarterly 平均要跨 **28.4** 个 prior sessions（最大 309），跨会话更新/删除平均 **14.8** 次（最大 94）；LongMemEval 对应为 1.9 个 session / 2.0 次更新。两者不是一个量级。
  - FAMA（weekly → quarterly）：A-Mem **71.82 → 40.78**；LangMem **71.16 → 39.14**；Mem0 **40.42 → 19.90**；MemoBase **43.60 → 15.18**。
  - reasoning 任务普遍接近 0–30，最好的 LangMem weekly 30.00，quarterly 11.00。
- **适用**：评测“记忆是否随用户境况变化而更新”，尤其是长期个性化。
- **失败条件**：FAMA 是作者定义的任务级分数，不是通用准确率；生成管线是模拟的，真实聊天噪声更多；分数不能和 CMB 直接横比。
- **对 mnemonic 的含义**：评测不能只看“最终答案对不对”，要单独统计“答案里是否用了已作废的旧值”。这应作为 150 题 A/B 的副作用指标，而不是只看得分。

### 2.11 Stop Listening to Me!：多轮本身会降低可靠性

- **来源**：*Stop Listening to Me! How Multi-turn Conversations Can Degrade LLM Reliability*，arXiv:2603.11394，2026-03。级别 **B**（17 个模型、3 个临床基准；非记忆系统）。
- **机制**：stick-or-switch 框架，把同一组选项拆成多轮顺序呈现，测“坚持正确答案/弃权”的 conviction 和“接受正确建议”的 flexibility。
- **量化（作者报告）**：端到端准确率和对错误建议的弃权平均最多掉 **30%**，部分模型 **65%**；从初始弃权转为接受错误建议与正确建议的比率接近，最高 **50%**；模型变大缓解一部分、加剧另一部分（更容易从弃权接受错误建议）。
- **适用**：任何多轮交互；说明“把信息分几轮说”本身就有成本。
- **失败条件**：临床多选题，不是开放聊天；测的是选项呈现顺序，不是记忆检索；不能直接折算成 CMB 题数。
- **对 mnemonic 的含义**：纠错不要靠“下一轮再解释一遍”；用户说“不是这个”时，系统应当立刻写一条新记录并作废旧槽位，减少后续轮次的歧义。

### 2.12 TWIST：检测矛盾与不过度干预是一对矛盾

- **来源**：*TWIST: A Proposed Benchmark for Intervention Quality in Conversational Memory*，arXiv:2609.28575，2026-09。级别 **B**（Track B 161 条人工校验，κ=0.85；其余 track 还是提案）。
- **机制**：四条 track：主动检测未解决的张力、用记录审查外发草稿、用当前信念回答同时保留 supersession 历史、治理敏感召回；每个检测指标都配一个表面匹配的 hard negative，专门惩罚“什么都flag”。
- **量化（作者报告，Track B v1.0）**：
  - flat-RAG 检出真矛盾 **0.76–0.97**，但误flag表面匹配的安全草稿 **16%–43%**。
  - 一个部署的 coherence-oriented 系统 specificity **0.98–1.00**，但只抓到 **42%** 真矛盾。
  - 归因准确率：需要检索的系统 **0.44–0.59**；给 gold evidence 后 **0.97–1.00**——作者判断这是 evidence-grounding 限制，不是推理限制。
  - 每个 gold contradiction 都能从证据本身检出（recall 1.000），说明瓶颈在检索覆盖/打包。
- **适用**：需要“该不该干预”的记忆系统；尤其适合评估“主动提醒旧矛盾”会不会过度打扰。
- **失败条件**：Track B 是草稿对齐，不是完整问答；161 条样本小；其余 track 未实例化。
- **对 mnemonic 的含义**：不要做全局“矛盾扫描 + 主动提醒”；只在被问到的槽位上做冲突提示。`index.js` 现在只要同一槽位有两个活值就提示“同一件事有两种说法”，应加“仅在被问到这个槽位时”与“最多一条”的限制。

### 2.13 Task Matters：高可信冲突比“有冲突”更伤

- **来源**：*Task Matters: Knowledge Requirements Shape LLM Responses to Context-Memory Conflict*，arXiv:2506.06485，2025-06。级别 **B**（多模型诊断框架，代码/数据公开）。
- **机制**：保持底层知识不变，跨任务引入受控的上下文-记忆冲突；比较高 plausibility（HPC）与低 plausibility（LPC）冲突，以及 rationale / context reiteration 的影响。
- **量化（作者报告）**：
  - GPT-5.2 在参数知识任务上：无冲突 **89.2** → HPC **33.7** → LPC **71.8**；说明“高可信的干扰”比“冲突本身”更致命。
  - RAG 任务 HPC vs LPC 的差距：MistralMoE-7B **41.2 vs 54.4（−13.2）**，Qwen2.5-7B 60.2 vs 67.1（−6.9），GPT-5.2 59.7 vs 66.6（−6.9）。
  - rationale / context reiteration 会提高对上下文的依赖：对“只该看上下文”的任务有帮助，对“该用参数知识”的任务有害。
- **适用**：解释为什么“把旧值和新值都放进块里”会让模型选错；也解释为什么“重复上下文”不是 universal fix。
- **失败条件**：任务是人造受控冲突，不是真实聊天；HPC 的“可信”由构造决定；模型版本较新（GPT-5.2），外推到 qwen-flash 要打折。
- **对 mnemonic 的含义**：旧值不要和新值并排成两条“都可信”的证据；要把旧值降级成“以前的说法”，且当前值放在块尾 `nowLine`（已有）或事实卡前置。仅仅加一句“按最近那条”不够。

### 2.14 CiteGuard-RAG：句级校验比“让模型再想想”有用

- **来源**：*CiteGuard-RAG: A Validation-Centered AI System for Evidence-Grounded Question Answering*，arXiv:2609.15830，2026-09。级别 **B**（400 题，三个数据集；作者自测）。
- **机制**：混合语义-词法检索 → 引用约束生成 → 句级 grounding 校验（引用有效性 + 词面重叠 + 语义支持）→ 接受/拒答/单次重生成。
- **量化（作者报告）**：受控住房法数据 **99.1%** retrieval accuracy、**98.3%** grounded-answer、**98.3%** citation validity，校验未发现幻觉；去掉 validation 后 grounded accuracy 明显下降而 retrieval accuracy 不变；外部域（PrivacyQA/CUAD）citation validity 仍强，但 evidence utilization、span alignment、refusal calibration 变难。
- **适用**：证据在上下文里、答案必须逐句可核对的 QA；与 mnemonic 的 `[M#]` 场景同构。
- **失败条件**：98.3% 是单域受控结果，作者自己提示 0.0% 幻觉要按研究设置解释；换域后拒答校准变差；句级校验需要可靠的“支持/不支持”判定，纯字符串匹配只能覆盖日期/数字/人名。
- **对 mnemonic 的含义**：`RECALL_RULES` 第 6 条 + `RECALL_TAIL` 已经是“逐句可指到 `[M#]`”；下一步是确定性的出站校验（日期/数字/人名是否在对应 `[M#]` 原文里），而不是第二次自由生成。

### 2.15 CiteShade：引用通道本身可被“洗白”

- **来源**：*CiteShade: Citation Laundering in Multi-Source Retrieval-Augmented Generation and Its Counterfactual Defense*，arXiv:2609.15660，2026-09。级别 **B**（攻击 + 防御；安全会议风格）。
- **机制**：攻击者控制一个来源，诱导模型输出错误答案，并把答案归因给一个不支持它的可信来源，同时正确答案的证据仍在上下文里。
- **量化（作者报告）**：多源多跳 QA 上错误答案率 **0.01 → 0.68**；删掉恶意来源后恶意来源是因果驱动；漏洞与模型“爱引用”的程度相关而非规模，显式指令下 CLR **0.84**，无指令 **0.64**；困惑度过滤和“引用支持检查”各自都不够，作者提出 counterfactual defense（验证哪个来源真正驱动了答案）。
- **适用**：任何把 citation 当审计线索的系统；提醒“模型标了 [M#]”不等于“这句话真的由该条支持”。
- **失败条件**：攻击需要控制一个来源；聊天记忆里“来源”是用户原话，攻击面不同；但“引用错行/引用不支持”的失败模式完全适用。
- **对 mnemonic 的含义**：出站不要只检查“有没有 `[M#]`”，要检查“被引的那条原文是否真的包含这个日期/数字/名字”。这也是 CiteGuard 的句级校验能落地的最小版本。

### 2.16 Regimes：LongMemEval-S 的主要失败是 reconciliation

- **来源**：*Regimes: An Auditable, Held-Out-Gated Improvement Loop Demonstrated on LongMemEval with ActiveGraph*，arXiv:2606.10241，2026-06。级别 **B**（作者自测，5 个 seeded split，pooled 描述性）。
- **机制**：事件溯源 runtime + 失败诊断 + 在 pipeline seam 上提出补丁 + 静态检查/沙箱/样本内/held-out 门控；用 LongMemEval-S 做演示。
- **量化（作者报告）**：LongMemEval-S 上的主导失败不是 retrieval，而是 **reconciliation**——“证据已经在 assembled context 里，reader 仍答错”；在 5 个 held-out split 上，reader prompt 修复把最终准确率提高 **+0.05 到 +0.10**（4 个 split），另一个 over-promotion split **+0.01**；只有两个 split 单独显著，pooled 只作描述。
- **适用**：说明“证据在块里但答错”是独立失败类；prompt 层修复有真实但不大的上限。
- **失败条件**：5 个 split 共享同一个 500 题池，不能当独立重复；作者自己说 failure-regime taxonomy 的边际价值还是 open question。
- **对 mnemonic 的含义**：这与《答题忠实度》里 209 道“证据在块里仍答错”的多标签口径一致；不要期待一个大 prompt 改动能吃下全部，应该按 failure regime 分开打（旧值、时间、纠错、引用）。

### 3.1 不建议动的点

- **不要**在 `renderRecallBlock` 里新增“第 8 条纪律”。`RECALL_RULES` 已经 7 条，FollowBench/前一轮实测都说明约束数量接近上限；只替换第 6 条或尾注。
- **不要**在写路径加 LLM judge 判“是否矛盾”。TOKI 的审计显示，LM judge 在写路径会引入 replay/belief-drift/audit erasure 三类异常；mnemonic 的槽位规则已经够用。
- **不要**把 `profile` 放到证据前面。现有注释“先读画像再读原话，模型容易照着画像编”与 Whale 的“事实卡前置”不冲突：事实卡是“核心/约定”，画像是“长期印象”，两者要分开；本轮不做大改。

## 4. 150 题子集验证方案

### 4.1 样本与配对

- 子集文件：`.tmp/cmb-local/rows-weak150.json`，已确认 **150** 条：P01 24、P12 29、P14 27、P16 20、P17 26、P20 24。
- 同一批 id、同一组命中缓存、同一答题模型、同一判分模型、`temperature=0.3`；A/B 只换一个变量（渲染/路由/规则），不重新检索。
- 主指标：整题通过数（配对）；同时记录 `b`（基线错→实验对）、`c`（基线对→实验错），用 McNemar exact 看方向，不只看净增。
- 统计门槛：150 题配对在 baseline 65% 左右、discordance 25% 左右时，MDE 约 **10–11pp（15–17 题）**；任务书的“净增 +15”刚好在门槛上，所以必须同时看 `b/c` 和分桶方向，不能把 +15 当强显著。

### 4.2 分阶段判据

| 阶段 | 改动 | 主判据（150 题） | 副作用/回滚 |
|---|---|---|---|
| S1 | M1 读路径不渲染作废旧值 + M2 槽位定序 | 旧值/矛盾桶净 **≥ +8**；全子集净 **≥ +10** | 历史题（问“以前”）不回退 >2；过度弃权 ≤ +3；否则回滚 |
| S2 | M4 时间路由 + M5 距今 N 天 | 时间/相对日期/时间约定三类合计净 **≥ +8**；非时间题不回退 >3 | 日期误删 ≤3；答案长度 ≤ +20%；否则回滚 |
| S3 | M7 纠错状态变更 | 纠错桶净 **≥ +6**；旧值桶不回退 | 纠错误触发 ≤3；答案长度 ≤ +20%；否则回滚 |
| 收口 | S1+S2+S3 | 全子集净 **≥ +15**，且至少两个分桶方向为正 | 任一阶段净负或过度弃权 > +10 → 不带入 714 |

> 分桶按判分 JSONL 的标签/失败类型分组，不按 P 号猜；P 号只用于抽样和分层，不直接等于七个薄弱标签。

### 4.3 可复制命令（本地/服务器按现有脚本）

本地渲染 A/B（已有脚本，固定命中、只换渲染/尾注）：

```powershell

```

服务器主链路（涉及检索/路由的改动必须走同一份命中；`/root/cmb-work/`）：


### 4.4 失败时怎么记

- 子集净增 < +15：记录“证伪”，写清是哪个机制没过（例如“读路径过滤让历史题掉了 4 题”），不硬上 714。
- 分桶方向为正但总量不够：保留该机制，下一轮只叠加下一个机制；不要一次上三个。
- 过度弃权 > +10：优先回滚“说记不清”类措辞，保留确定性过滤。

## 5. 明确不采用

| 方案 | 依据 | 不采用原因 |
|---|---|---|
| 训练 contradiction updater / retriever（HiCoMER 式） | 2.5 | 需要标注的维护实例和 pairwise ranking；聊天场景没有团队层级；收益在两个自建数据集上，未在 CMB 验证 |
| 用 RL 训“当前值/旧值”奖励（Supersede 式） | 2.1 | 需要标注和训练设施；Qwen2.5-3B 训后也只有 16.7%，短期救不了 714 |
| 写路径加 LLM judge 判矛盾（TOKI 审计的基线做法） | 2.4 | 引入 replay/belief-drift/audit erasure 三类写时异常；成本高、不可回放 |
| 用余弦相似度阈值检测矛盾 | 2.2 | AUROC 0.59，矛盾比复述更相似；任何阈值 precision 上限 0.667，做不到安全自动规则 |
| 时间旅行/point-in-time 默认检索 | 2.7 | knowledge-update 有 80% R@10，但 temporal-reasoning 从 50% 掉到 37.5%；不是免费增益 |
| 只在 prompt 里写“这条已作废” | 2.3 | Graphiti 44.2% → 38.4%（只 prompt），output filter 19.0%，读路径过滤才是 0%；标签不是执行 |
| 全局矛盾扫描 + 主动提醒 | 2.12 | flat-RAG 误flag 16–43%；coherence 系统只抓 42%；聊天里会变成过度打扰 |
| 加大记忆预算/换更大模型 | 2.1 | 24 倍对话长度 68%→28%；按比例加预算 28%→28%；前一轮实测 300 字≈3 题，低于 MDE |
| 把 citation 当正确性证明 | 2.15 | CiteShade 错误率 0.01→0.68，引用可被洗白；只能做事后支持校验 |
| 独立两段式“先抽证据再答” | 答题忠实度文档 §3.3 | Qasper 同模型 47.02→39.08 F1；块只有 4 行时抽取只会多一个失败点 |
| free-form self-review / 再检查一遍 | 答题忠实度文档 §7.2 | Huang et al. 三次调用全面降分；没有外部判据的自纠是负期望 |

## 6. 与另外两份调研的衔接

- **《答题忠实度》**已经给出 P0 逐句 `[M#]`、P2 日期只抄、P3 boundary 类别化、P5 盲验证。本篇补的是它没有展开的三件事：**读路径执行作废**（M1/M2）、**时间题单独路由**（M4/M5）、**纠错落成状态变更**（M7）。三者的学术依据分别是 Revoked、LongMemEval/TReMu、Stop Listening/TWIST。
- **《高分实现拆解》**给出“事实卡前置、时间路由、一条肯定式约束”的工程证据；本篇给出对应的论文数字和失败条件。两份文档的交集是“时间路由”和“不要叠规则”，不重复造轮子。
- 本轮不改 `boundary.js`、不做 rerank、不做多跳扩展；这些留给后续轮次。
