## 〇、不可让渡的四条

1. **禁止在生产工作区留下一次性脚本与备份**
   - 调试脚本放 `/tmp/` 或 Agent scratch，**用完 `rm -f`**。
   - 手工备份一律 `/root/bak2/<批次-主题>/`，不许平铺、不许留在业务目录。

2. **禁止绕过门禁**
   - `契约检查.mjs` 有任何红项 → **禁止发布**。
   - 不许删测试/弱化断言让测试变绿。
   - 不许用 `--no-verify` 或跳过自检。

3. **禁止以注释/文档为证据下结论**
   - 注释是「当时的说法」，不是事实。审计顺序：**读代码 → 实测 → 最后读注释 → 矛盾以实测为准**。

4. **文档只写现状**
   - 规范、规矩、手册不写沿革、批次号、旧做法；标题不带日期、版本号、实例名和无信息量括注。
   - 细则见 `代码规范.md` §十六；过程记 `共享/变更.md`，淘汰内容进 `_归档/`。

## 一、目录规范

> **目标**：易维护、易阅读、易增添功能。

### 1.1 四层目录模型

生产代码按架构层级归位，**目录层级 = 架构层级**：

```
共享/工具/

├── 判据/          L1.5 纯判据：只回答问题，不写盘
```

### 1.2 模块对称铁律（新增功能强制）

**新增任何功能，必须在对应层目录下创建独立模块，保持模块对称。**

| 功能规模 | 目录形态 |
| :--- | :--- |
| 单文件即可 | `<层>/<模块名>.mjs` |
| 需要 2 个以上文件 | `<层>/<模块名>/` 内含 `index.mjs`（对外唯一入口）+ 内部文件 |
| 需要专属数据 | `<层>/<模块名>/` + `数据/<模块名>.json` |
| 需要专属页面 | `<层>/<模块名>/` + `页面/<模块名>.html` |

**五条强约束**：

1. **禁止在 `共享/工具/` 顶层新增平铺 `.mjs`**（顶层只保留上述 9 个目录）。违反即契约红灯。
2. **模块目录名 = 功能名**，禁止 `新建文件夹` / `misc` / `tmp`。
3. **对外只用 `index.mjs`**：模块内部可自由拆分，外部只能 `import ... from './<层>/<模块名>/index.mjs'`。
4. **同级模块禁止互相 import 内部文件**，必须经对方 `index.mjs`。
5. **跨层调用只能向内**：`出口/` → `接口/` → `领域/` → `判据/` → `核心/`，反向即违规。

### 1.3 测试目录镜像铁律

**测试目录必须镜像生产目录结构**，一个生产模块对应一个测试位置：

```
共享/工具/测试/
├── 核心/
│   ├── 底层.test.mjs
│   └── 状态.test.mjs
├── 判据/
│   └── 睡态.test.mjs
├── 领域/
│   ├── 困意.test.mjs
│   └── 工作/
│       ├── 班次.test.mjs
│       └── 睡岗.test.mjs
├── 接口/
│   └── 隧道.test.mjs
└── 出口/
    └── 契约.test.mjs
```

**四条强约束**：

1. 测试文件路径 = 生产文件路径 + `.test` 后缀（目录层级完全一致）。
2. 一个模块目录下的测试放在同名测试目录内，**禁止把测试全平铺在 `测试/` 根层**。
3. 新增模块若无对应测试 → 契约红灯。
4. 测试目录不得出现生产目录里没有的模块（防悬空测试）。

### 1.4 依赖检查（生成代码时强制）

**每次生成代码，必须先做依赖检查，再落笔。**

| 检查项 | 方法 | 不合规处置 |
| :--- | :--- | :--- |
| **层级方向** | 该文件属于哪一层？import 的是否都在同层或更内层？ | 反向依赖 → 抽接口 / 下沉 |
| **循环依赖** | `grep` 目标文件是否已被依赖方引用 | 有环 → 必须消除 |
| **判据重复** | 要写的判断是否已有唯一实现 | 已存在 → 改为 `import` |
| **数据写方** | 要写的数据是否已有唯一写方 | 已有 → 走该写方入口 |
| **配置硬编码** | 路径/端口/密钥/阈值是否出现字面量 | 有 → 改配置或环境变量 |
| **实例名** | 是否出现实例名/QQ 号/实例路径 | 有 → 改占位符 |
| **模块对称** | 是否在新建目录而非平铺 | 平铺 → 建模块目录 |

**依赖检查不合格 = 代码不得输出**，必须先给合规方案。

### 1.5 违规拒绝与合规替换（强制）

发现（或自己被要求做）违规操作时，**必须拒绝并给出合规替换**，不得默默执行。

| 违规操作 | 合规替换 |
| :--- | :--- |
| 在 `工具/` 顶层新增 `.mjs` | 建 `<层>/<模块名>/index.mjs` |
| 新模块不建目录、塞进已有文件 | 新建模块目录 |
| 测试平铺在 `测试/` 根层 | 建镜像子目录 |
| 新增模块无测试 | 补镜像测试 |
| 跨层反向 import | 抽接口 / 下沉实现 |
| 复制已有判据再写一遍 | 改 `import` |
| 硬编码实例路径/实例名 | 占位符 / 环境变量 |
| 硬编码密钥/端口/IP | 配置文件 / 环境变量 |
| 固定临时文件名 | `pid + random` |
| 备份放在业务目录 | `/root/bak2/<批次-主题>/` |
| 删测试/弱化断言让门禁变绿 | 修实现或修正错误断言 |

**表达方式**：说清违反哪条 + 给等价合规方案 + 说明代价。禁止冷冰冰拒绝，也禁止默默照做。

### 1.6 存量迁移路线（分阶段，禁止一次性搬动）

当前 `共享/工具/` 是**扁平存量**（144 个 `.mjs` 平铺顶层）。**禁止一次性搬动** —— 会同时破坏契约检查、心跳表、全部相对 import 与 271 个测试。

| 阶段 | 动作 | 验收 |
| :--- | :--- | :--- |
| **P0（当前）** | 存量保持扁平；**新增代码立即按 §1.2 建目录** | 契约不新增红项；新模块有镜像测试 |
| **P1** | 搬迁 `核心/` → `判据/`（依赖最少、影响面最小） | 契约全通 + 心跳表路径更新 + 测试镜像同步 |
| **P2** | 搬迁 `接口/` → `领域/`（一次一个模块，一次一提交） | 每次搬迁后全量门禁全绿 |
| **P3** | 搬迁 `出口/`（`面板.mjs` 单独排期，需拆分） | 同上 |
| **P4** | 数据/页面/资源归位到 `数据/` `页面/` `资源/` | 同上 |

**每阶段内部**：一次只搬一个模块 → 更新所有调用方路径 → 更新测试路径 → 跑全量门禁 → 记账。
**硬约束**：迁移期间**不得同时改逻辑**。

## 三、保洁与门禁机制

### 3.1 三道闭环

| 闭环 | 触发 | 性质 |
| :--- | :--- | :--- |
| `契约检查.mjs` | 每次改动后 / 心跳每周 | **硬门禁**，红即禁止发布 |
| `目录卫生.mjs` | 每日 04:20 | **自动保洁** |
| `daily-check` | 每日 12:10 | **巡检**，进待办不改代码 |

### 3.2 契约检查关键项

| 项 | 判定 |
| :--- | :--- |
| 目录洁癖 | 顶层无乱放文件；`记忆/` 顶层无 `.log`；`工具/` 无 `.bak`/`patch_`/`fix_`/`tmp`；无 `.dsh-meow` |
| **工具目录结构** | `工具/` 顶层只允许 9 个目录；顶层新增平铺 `.mjs` → 红 |
| **测试镜像** | 每个生产模块有镜像测试；测试不得出现生产没有的模块 |
| 工具白名单 | 不许留 0 调用的 `schedule_*` |
| 桥配置 | 每个键必须有代码在读 |
| `ENTRY_GUARD` | 每个 `.mjs` 必须有入口守卫（见 `代码规范.md` §7.5） |
| 参数守卫 | `--help`/未知参数/缺值必须在读写盘前退出 |

执行：`node 共享/工具/出口/契约检查.mjs` → 期望 `0 项不对`。

### 3.3 目录卫生规则

| 动作 | 规则 |
| :--- | :--- |
| 顶层 `.log` 归位 | `记忆/*.log` → `记忆/日志/` |
| 日更文件 | 超 7.5 天解除顶层软链接；实体归子目录 |
| 按月归档 | 超 7.5 天归 `归档/历史按月/YYYY-MM/` |
| 日志裁剪 | 超 5000 行 → 留 2500 |
| 视频缓存 | `.mp4` 超 3 天 |
| 分镜图 | `BV*.png` 超 **7 天** |
| 屏幕历史 | 只留最近 50 张 |
| 下载中转 | 超 2 天清空 |

**判定原则：能不能一键重建**。能重建的短留（`.mp4` 3 天 / `.png` 7 天），不能重建的长留（`.srt` / `.omni.json`）。
`--dry` 必须**零写入**（含不创建目录）。

### 3.4 体检的错误分类

| 级别 | 含义 | 计入问题数 |
| :--- | :--- | :--- |
| `ok` | 正常 / **本机未启用（跳过）** | 否 |
| `warn` | 需人看一眼 | **否** |
| `bad` | 真故障 | 是 → `exit 1` |

**可选组件判定**：先判断这台机器该不该跑它（§2.5）。可选服务/端口未启用 → `ok(未启用)`。

**端口探测用 `/proc/net/tcp`，不用 `curl`**（微秒级、零副作用、不触发风控）：

```js
function 端口在听(port) {
  const hex = Number(port).toString(16).toUpperCase().padStart(4, '0')
  for (const f of ['/proc/net/tcp', '/proc/net/tcp6']) {
    try {
      const txt = fs.readFileSync(f, 'utf8')
      for (const line of txt.split('\n').slice(1)) {
        const c = line.trim().split(/\s+/)
        if (c.length < 4) continue
        if ((c[1] || '').endsWith(':' + hex) && c[3] === '0A') return true
      }
    } catch { /* 读不到就跳过 */ }
  }
  return false
}
```

**「日志陈旧」记 `warn` 不记 `bad`**。

### 3.5 心跳调度

### 3.6 `.tmp` 写入规范

```js
const tmp = p + '.tmp-' + process.pid + '-' + Math.random().toString(36).slice(2, 8)
```

固定临时名在两进程/两次写入相撞时会互相灌半截内容。**新增写盘代码必须照此格式。**

`{{BOT_ROOT}}` `{{DSH_ROOT}}` `{{BOT_DISPLAY}}` `{{ALT_BOT_DISPLAY}}` `{{SELF_UIN}}` `{{OWNER_UIN}}` `{{GROUP_UIN}}` 各端口 `{{*_TOKEN}}` `{{SVC_*}}` `{{PATCH_SCRIPT}}` `{{PATCH_DIR}}`。

**三条硬禁止**：
1. 通用代码禁止硬编码实例路径。
