## 一、注释骗人（最危险的一类）

### C-01 `走路.mjs` 距离比例：注释说「用中位数」，代码硬返回常量

- **现象**：所有路程时间 = 坐标直线距离 × 0.55，与地图 `t` 标定无关。
- **根因**：`距离比例()` 遍历地图累加 `总`/`n` 共 15 行后**直接 `return 0.55`**，累加结果一次未用；注释「用中位数而不是平均数：一两个坐标标错的地点会把整体比例拉偏」描述的是**未实现**的方案。
- **修法**：真正实现中位数 + 两条保护（有效样本 < 3 回 0.55；中位数越界 0.2~1.5 回 0.55）。实测 19 样本中位数 0.5453。
- **规范**：代码 §三「注释」第 1 条。

### C-02 `_状态.mjs` 批判固定临时名，自己却用固定临时名

- **现象**：`saveState` 的临时名是 `${p}.tmp${process.pid}`，只有 pid、无随机。
- **根因**：上一段注释刚批判「`睡眠阶段.mjs` 那份原子写的临时名固定是 `file + '.tmp'`，两个进程同时写会往同一个 .tmp 灌半截」，自己紧接着用了同形状的写法。
- **修法**：改为 `pid + 随机 6 位`，与 `_底层.写档` 统一。
- **规范**：目录 §3.6「.tmp 写入规范」；代码 §三「注释」。

### C-03 `投递留言.mjs`：「最多 3 条别轰炸」实际每小时 36 条

- **现象**：`MAX_PER_RUN = 3`，cron 每 5 分钟 → 每小时上限 36 条。
- **根因**：注释把「不轰炸」寄望在单个常量上，而真正的刹车是 `DAY_CAP` 与 `DEDUP_HOURS`。
- **修法**：注释改实话；补 `DAY_CAP`（早安/日报/晚安 1 次，想聊 3 次，被想起/要钱/撒娇 2 次）。
- **规范**：代码 §三「注释」。

### C-04 数字类断言持续腐化

- **现象**：`主动戳.mjs` 注释「import 全部 **122 个**工具脚本」，实际已 **149 个**。
- **修法**：去掉写死数字，改「全部工具脚本」。
- **规范**：代码 §三「注释」「注释里任何数字都是未来的谎言」。

### C-05 crontab 注释与源码分离导致误判

- **现象**：误以为 `自主行动.mjs` 源码里有「每分钟只检查 nextAt」，实际那句在 **crontab 注释**里。
- **修法**：撤回该判断并记录。
- **规范**：代码 §三「注释」 第 1 步「先读代码行为」。

## 二、死字段（字段存在但判据输入是常数）

### C-06 `饥饿.json.饱腹` 恒为 55，三处「饿不饿」判据从未生效

- **现象**：`自动作息:341` / `醒来:119` / `状态推进:232` 三处都 `load('饥饿.json').饱腹 <= 10`，而该字段是死字段（`吃()` 存的时候 `out` 里没有它，`...记账` 带旧值），停在历史数字，而 `读()` 现算是 98。
- **修法**：统一为 `饥饿.饿着(阈)`（现算唯一判据）。
- **规范**：代码 §一「判据唯一 / 单一真源」；代码 §十四「维护与重构」 死字段。

### C-07 `existential` 冻在 49 共 10 天无人发现

- **现象**：唯一写方 `奖惩.mjs:232`（条件 `if (k.存在能量)`）随 `认事.mjs` 停用，字段从 11-04 冻住；`状态变更.log` 26 行全是 physical，它零命中（因为事件只变 0.4~0.8，而该日志阈值是 5 点，永远写不进去）。
- **修法**：`_总线.记存在()` 单独记 `存在层.log`；`状态推进` 补时间驱动的漂移。
- **规范**：代码 §十四「维护与重构」 死字段；代码 §一「判据唯一 / 单一真源」。

### C-08 `valence`/`arousal`/`drive` 三个情绪字段是摆设

- **现象**：`arousal` 全仓无写点无读点；`valence` 只有读没有写（永远 50）；`drive` 被读 4 处但无写点（永远 `calm`，`anxious` 分支从上线起未执行）。

### C-09 渴缺口恒为 0（反向死字段：写方删了读方还在读）

- **现象**：`缺口.mjs` 读 `st.body.渴`，而 `状态推进` 已写了 `delete b['渴']`。`Number(undefined ?? 0) = 0` → 渴强度恒 0，该缺口从未触发。
- **修法**：改读 `饱渴.读().水百分比`（唯一真源）。实测输出「缺渴 43%」。
- **规范**：代码 §一「判据唯一 / 单一真源」；代码 §十四「维护与重构」。

### C-10 `内心.mjs` 五样全读错层级 → 三个分支永不进入

- **现象**：好感/熟悉/怨/别扭/想要 全读在根对象上，而真实结构是 `{people:{uin:{...}}}` / `{当下想要:[...]}` → 全是 undefined → 每天念同一段「没有非做不可的事」。

## 三、空 catch 吞掉真错误（症状是「功能从来没生效」）

### C-11 `endSleep` ReferenceError 被吞 → 睡醒结算静默失败一周

- **现象**：`saveState(…, stateSnap)` 用的 `stateSnap` 从未定义（`tickSleep` 有、这里漏了）→ `ReferenceError` → 被最外层 `catch { return fail() }` 吞成失败。11-10 起每次睡醒结算都静默失败，records / 欠觉账 / 补课全停，而梦余味的「情绪已用」照样被标掉。
- **修法**：补 `const stateSnap = clone(state)`；并把 `catch` 改成必须写 `醒来.log`。
- **规范**：代码 §七「错误处理」 空 catch 红线。

### C-12 `resting` 作用域不够 → 整段疾病/体温罚从来没执行

- **现象**：`act`/`resting` 只在「醒着」分支声明，下面疾病段要用 `resting` → `ReferenceError` 被 `catch {}` 吞掉 → 疾病/体温罚整段不执行。
- **修法**：提到外层作用域。
- **规范**：代码 §七「错误处理」；代码 §六「模块 / 类」。

### C-13 收摊时 stdout 与 stdout 一起丢

- **现象**：`endSleep` 被以 `stdio:'ignore'` spawn，而错误只 `return fail()` 不写日志 → 整天无人知道结算没发生。
- **修法**：失败必须 append 到 `醒来.log`。
- **规范**：代码 §七「错误处理」「下游有 stdio:'ignore' 必须写日志文件」。

## 四、门禁/体检假红灯（比没有体检更糟）

### C-14 `生活体检` 连败 21 次

- **现象**：连败账 `生活体检.连败 = 21`，待办永远挂假警报。
- **根因**：第 1 项查面板 `8788`，连不上记 `bad → exit 1`；而该机 `fish-panel.service` 本就停用（角色=`scripts`）。
- **修法**：先探端口，没进程在听 → `ok(未启用)`；同时把「日志陈旧」从 `bad` 降为 `warn`。连败 21 → 0。
- **规范**：目录 §3.4「体检的错误分类」。

### C-15 `同步QQ状态` 一天失败 459 次

- **现象**：心跳日志 `[失败] 同步QQ状态` 459 次/天（`fetch failed`）。
- **根因**：协议端在该机停用，但心跳每 2 分钟调用 → `fetch` 失败 → `exit 1` → 判任务失败。
- **修法**：协议端端口不在听 → 打一行说明 + **`exit 0`**（不算失败）。
- **规范**：代码 §七「错误处理」「退出码语义必须与调度器解释一致」。

### C-16 `体检-基础` 固定 7 条假问题 / `全套验收` 固定 5 红

- **现象**：`✗ dsh-bot / fish-panel / fish-upstream / 面板:8788 / 接口中转:39401 / OneBot WS:8090 / OneBot HTTP:3011` 每天固定；全套验收 `✗ dsh-bot / fish-panel / napcat-fish / 面板端口 / 群列表`。
- **根因**：① 服务/端口列表写死，不看本机角色；② `napcat-fish` 这个服务名在该机根本不存在（实际叫 `napcat`）。
- **修法**：角色感知（`参数.json` `开关.机器人角色` = `full`/`scripts`），可选组件未启用记 `ok(未启用)`；修正服务名。7 条 → 0 条；5 红 → 1 红。
- **规范**：目录 §2.5「服务角色声明」；目录 §3.4「体检的错误分类」。

## 六、测试污染与测试缺陷

### C-21 跑冒烟测试真戳主人

- **现象**：2026-11-16 凌晨群里出现一串「拍了拍你的ice」，`04:22 / 04:34 / 04:36 / 04:38 / 04:42 / 04:56`。
- **根因**：`主动戳.mjs` 发送逻辑全在模块顶层 → 冒烟测试「逐个 import 检查可加载」等于真执行一遍。
- **修法**：加 `ENTRY_GUARD`；用 `tcpdump` 抓 pid 才定位到 `node 冒烟1.加载.test.mjs` 连的 `127.0.0.1:3000`。
- **规范**：代码 §八「ENTRY_GUARD」。

### C-22 `契约检查` 被 import 时真跑一遍，写盘 538 次

- **根因**：顶层即主流程 + 末尾 `process.exit` → 冒烟子进程被带走，记成「主动退出」，等于加载测试从来没真测过它。
- **修法**：加 `ENTRY_GUARD`。
- **规范**：代码 §八「ENTRY_GUARD」。

### C-23 `t372.时间线` 沙盒目录从不创建 → ENOENT

- **现象**：`Error: ENOENT: open '/tmp/sb/proactive.json'`。
- **根因**：常量 `沙箱='/tmp/sb'`，整个文件无一处 `mkdirSync`；`/tmp` 被清（重启/systemd-tmpfiles）后第一个 `writeFileSync` 就炸。
- **修法**：`fs.mkdirSync(沙箱, { recursive: true })`。1 pass。
- **规范**：代码 §十一「测试」 隔离第 1 条补充。

### C-24 `t401.文档` 依赖本机 8788 → ECONNREFUSED

- **根因**：真连面板 HTTP API，而面板在 `scripts` 角色主机上刻意停用。
- **修法**：先探端口，没在听就整份 `exit 0` 跳过。1 pass。
- **规范**：代码 §十一「测试」「依赖外部服务的测试必须能跳过」。

### C-25 测试污染插件日志

- **规范**：代码 §十一「测试」 额外第 3 条。

### C-26 钉死字面量的脆断言

- **现象**：把锁名改为「父目录名+basename」后 `t353` 出现 **9 项失败**。

### C-28 82 项测试失败是既有基线债务

- **证据**：两机插件 `lib` 文件数 **148 = 148**；`纪念日段` 在 `poll.js` **0 = 0**；`反客服腔` 在 `tool.js` **0 = 0**；同测试两机结果一致（`t406` 7红=7红 / `t663` 4红=4红 / `t507` 4红=4红）。

## 八、目录与模板事故

### C-33 模板里出现文件名带反斜杠的怪条目

- **现象**：模板自检 `[3/5]` 报 `FAIL node --check /tmp/tpl-selftest.xxx/ws/共享/工具\\睡态.mjs`，但 `ls` 看着正常、直接 `node --check 睡态.mjs` 也 OK。
- **根因**：python heredoc 批量转占位符时把目标路径拼成 `os.path.join(TPL, '工具\\\\睡态.mjs')`，在 `共享/` 下造出两个名字含反斜杠的条目（`工具\睡态.mjs`、`工具\全套验收.mjs`）。`ls`/`os.listdir('共享/工具')` 只看子目录所以查不到，而 `find -name '*.mjs'` 会抓出来交给 `node --check`。
- **修法**：`os.walk` 递归扫描所有含 `\` 的条目并删除。**常规检查项**：`find <dir> -name '*\\*'`。
- **规范**：代码 §十三「新建代码流程」 第 3 条。

### C-34 整份覆盖模板把实例数据带进去

- **现象**：模板自检 `[1/5]` 报「疑似残留」：`同步QQ状态.mjs / 体检-基础.mjs / 生活体检.mjs`。
- **根因**：从生产整份 `cp` 到模板，把实例名、QQ 号、`{{DSH_ROOT}}` 硬路径带进去了；且我在新写的**注释里**也带了实例名。
- **修法**：① 用 `sed` 转占位符；② **把身份改成配置驱动**（`留言板.自己名 = process.env.BOARD_BOT_NAMES || '{{BOT_DISPLAY}}'`，3 处 `n.by === '实例名'` 改 `自己名.includes(...)`）；③ 注释改通用说法。
- **规范**：代码 §十三「新建代码流程」 第 1、2 条。

### C-35 3D 房间整套已删但残留 5,639 行 + 932KB

- **现象**：`面板.mjs` 注释明确写「/room 2026-11-12 删除：3D 房间整套已经不在了」，但 `房间.mjs`(232行) / `房间页.html`(1339行) / `老界面.html`(**4068行，零引用**) / `three.min.js`(645KB) / `BufferGeometryUtils.js`(32KB) 全在。
- **四重证据**：① 无 systemd 单元；② 不在心跳表 55 条里；③ `面板` 无 `/room` 路由；④ `grep` 全目录 `.mjs` 零引用。
- **修法**：归档到 `/root/bak2/3D房间残留-<时间戳>/`。`three/` 2.0MB → 1.3MB。
- **规范**：目录 §2.3「共享空间治理」 `_归档/` 登记；代码 §十四「维护与重构」 大类/大文件。

### C-36 `面板试听/` 非标目录长期存在

## 九、磁盘与缓存

### C-38 `记忆/视频画面` 1.1GB，分镜 PNG 保留 30 天

- **现象**：`记忆/视频画面` 占 `记忆/` 的 92%（1.1GB / 1.2GB）。

## 十、并发与写盘

### C-40 固定临时名互相灌半截

- **现象**：`睡眠阶段.mjs` 的「原子写」临时名是固定的 `file + '.tmp'`；两进程同时写会往同一个 `.tmp` 灌，`rename` 出去的是对方的半截。
- **影响**：它写 `状态.json` / `睡眠.json` / `睡醒.json`，而她睡着时这条路每 20 分钟跑一次。
- **修法**：临时名统一 `pid + 随机`。
- **规范**：目录 §3.6「.tmp 写入规范」。

### C-41 多写方无锁 → 读-改-写窗口过大

- **现象**：`投递留言` 启动读整档 → 发送期间改内存 → 最后整档写回，跨越好几秒；日报/早间简报同时写会互相覆盖。
- **修法**：每条状态变更走 `_底层.改档()`（锁内重读 → 定位那一条 → 只改它 → 原子写）。
- **规范**：代码 §一「判据唯一 / 单一真源」；代码 §八「ENTRY_GUARD」。

### C-42 发送成功但未落盘 → 下一轮立刻重发

- **修法**：发送前落一条 `sending` 租约（2 分钟）；后来者看到新鲜租约跳过；崩溃最多 2 分钟后重试一次。
- **规范**：代码 §六「幂等」 幂等性。

### C-43 13 处裸 `.tmp-${pid}` 无随机后缀

- **范围**：`刷一刷`(×2) / `好感度-日结` / `快照` / `手账` / `留言板` / `缺口` / `自主学习` / `自主行动` / `面板`(一起听实时)。
- **修法**：全部补随机后缀，与 `_底层.写档` 口径统一。现状 0 处裸 pid。
- **规范**：目录 §3.6「.tmp 写入规范」。

## 十一、配置与默认值

### C-44 `额度.mjs` 默认代理 7891，而该机只有 7890

- **现象**：VPS 上跑额度查询会静默失败（`7891` 只在装有 `gemini-web2api` 的主机存在）。
- **修法**：按顺序探 `env > 7891 > 7890 > 兜底`（用 `/proc/net/tcp`）。实测 VPS 自动选 7890。
- **规范**：代码 §十二「配置与依赖」 配置集中；目录 §3.4「体检的错误分类」 端口探测。

### C-45 隧道探活只做 TCP connect → 假阳性

- **现象**：`7890` 「端口在听、控制面 alive:true、节点也选中」，但数据面 100% `SSL unexpected eof`。TCP 探活一路通过，进去 `curl` 才失败 → 每个墙外请求白等 15~25 秒。
- **修法**：新增 `出口通()` 真发 `generate_204`，结果缓存 60 秒。实测旧探活 `true`（假阳性）→ 新探活 `false`（正确）。
- **规范**：目录 §3.4「体检的错误分类」 端口探测的边界（探活要探「真能用」）。

### C-46 出口选择过宽 → 家宽抖了拖慢所有国内请求

- **现象**：`选出口()` 把所有非墙外域名判给家宽（天气/网盘/贴吧也跟着走）。
- **修法**：家宽白名单（`bilibili.com`/`b23.tv`/`hdslb.com`/`bilivideo.*`），其余「直连优先、失败回落」。
- **规范**：代码 §十「分层与依赖」 外圈可替换。

### C-47 家宽端口写死 1080，而某台机器根本没有

- **现象**：`有家宽` 恒真 → 那台机器 B 站永远失败。
- **修法**：读 `/proc/net/tcp` 自动探测。实测两台自动判出 `true` / `false`，B 站均走可用路径。
- **规范**：代码 §十二「配置与依赖」；目录 §3.4「体检的错误分类」。

### C-48 `FLEET_TOKEN` 变量名与注释不一致

- **现象**：注释写 `HAJIMI_FLEET_TOKEN`，代码读 `FLEET_TOKEN`，照注释配的人会发现「设了没生效」；且默认空字符串 = 不校验。
- **修法**：双名兼容（新名优先）。
- **规范**：代码 §三「注释」 第 3 步；代码 §十二「配置与依赖」。

### C-49 `DROWSY_AFTER_MEAL` 是假开关

- **现象**：注释说「挂 0 就整条熄火」，但全仓无任何一处设 `=0`，闸从未关上。
- **修法**：做成真能关（环境变量 或 `参数.json` 的 `开关.食困 = false`），并给 `参数.json` 补 `开关` 段。
- **规范**：代码 §十四「维护与重构」 假开关。

### C-50 `请求槽位` 两个分支超时可配性不一致

## 十二、安全

### C-51 出站消息绕过插件三道闸

- **现象**：`投递留言` / `发表情` / `发卡片` 原来各自 `fetch` 协议端，绕过 `blocked.js`（封禁 action）、`allowlist.js`（目标白名单）、`sensitive.js`（内容审计）→ 一条 `--谁 陌生人` 的手测命令就能绕过白名单。
- **修法**：收口到 `发送口.mjs`（自己读同一份配置，规则与 lib 一致，有 `t608` 对比两边判定）。
- **规范**：代码 §九「第三方封装」 适配器边界。

### C-52 短觉/微睡凭空记欠觉

- **现象**：线上一次 4.9 分钟微睡记 +7.92 欠觉，把欠觉从 8.9 抬到 16.8，体力封顶被压到 63。
- **根因**：任何 `endSleep` 都按「整夜 8 小时」结算。
- **修法**：**不足 4 小时按打盹处理**，不增加也不衰减欠账（判据只看时长，不看钟点）。
- **规范**：代码 §六「幂等」 幂等性。

### C-53 睡岗次数上限写死 3 → 概率形同虚设

- **现象**：各班「每分钟概率 × 时长」期望 3.00~6.00，固定上限 3 → 除最短班外每次都打满。
- **修法**：`睡岗上限(班, 配)` = 期望 × 1.5，最少 6（参数显式值仍优先）。实测 6/6/7/6/6/9/6。
- **规范**：代码 §四「数值审查三问」。

### C-54 疾病值可叠到 +125/h 无上限

- **现象**：所有加法项同时命中可叠到 +96/h，乘 1.3 = **+125/h** → 0 到 600（得病线）只需 4.8 小时。
- **修法**：封顶 60/h（最坏也要 10 小时才病倒）。
- **规范**：代码 §四「数值审查三问」 第 2 问。
