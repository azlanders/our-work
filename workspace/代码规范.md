# AI 代码规范

> **性质**：强制。违反不得输出，除非主人明确同意风险。
> **边界**：本文只管「代码怎么写」。目录/门禁/运维见 `目录与文件规矩.md`。案例见 `工程案例库.md`。

---

## 不可让渡（违反即回滚）

1. 不硬编码 路径 / 端口 / 密钥 / 实例名 / QQ 号
2. 不复制粘贴同一逻辑 3 次以上
3. 不复用「已存在判据」，改 `import`
4. 不写固定临时文件名（必须 `pid + random`）
5. 不用空 `catch {}` 吞主流程 / 结算 / 调度错误
6. 不在 `共享/工具/` 顶层新增平铺 `.mjs`
7. 新增模块必须建目录 + 镜像测试
8. 不删测试 / 弱化断言让门禁变绿
9. 不跨层反向 import
10. 不凭注释/旧批次号推断现状 —— 先读代码 → 再实测 → 最后看注释

## 一、七条核心原则

| 原则 | 判据 |
| :--- | :--- |
| 可读性 | 判据唯一 + 单一真源 |
| 单一职责 | 一句话说不清（含「和」）→ 该拆 |
| 依赖倒置 | 只能向内：`出口→接口→领域→判据→核心` |
| 关注点分离 | 算完返回，不顺手写盘 |
| 可测试性 | 写盘脚本必须有沙盒变量 |
| 无重复 | 同一判据 ≥3 处即红灯 |
| 童子军规则 | 每轮至少做一件净收益的事 |

**判据唯一**：判断只能有一份实现（`判据/睡态`、`判据/在干嘛`、`判据/占用`、`核心/账本`、`核心/恢复目标`、`判据/关系档`）。
**单一真源**：数据只能有一个写方（`状态.json`→`saveState`；`资产.json`→`改档`；`自主.json`→`自主状态.改`；睡眠结算→只挂 `endSleep`）。

---

## 二、命名

| 类别 | 规则 |
| :--- | :--- |
| 意图 | 准确表达「做什么」，禁止 `data`/`info`/`tmp`/`obj` |
| 长度 | 与作用域成正比；禁止单字母（短循环 `i`/`j` 除外） |
| 名词 | 类 / 对象 / 数据档 → `睡眠段`、`缺口台账` |
| 动词 | 函数 → `结算欠`、`标跳过` |
| 布尔 | 读起来像判断句 → `是入口`、`在听` |
| 常量 | 全大写或语义化 → `MAX_TRY`、`体力目标` |
| 批次标记 | `// 关键词 YYYY-MM-DD（批次NNN）：改前 → 改后`（全仓唯一可搜索） |

## 三、注释

**注释即债务**：能靠提取函数/改命名消除的，先改代码。

**只写「为什么」**，不写「做什么」。允许例外：法律 / 警示（`// 不要改这里，因为…`）/ TODO（**必须带日期+责任人**）。

**三条硬禁止**：
1. 禁止以注释为证据下结论（「已修好了」「链路作废了」「判据只此一份」= 待验证假设）
2. 禁止只改代码不改注释（失效注释必须同轮更新/删除）
3. 禁止保留死注释（作废说明挪 `共享/变更.md`，代码留一行指针）

**审计顺序**（不得颠倒）：读代码行为 → 实测 → 读注释 → 矛盾以实测为准。

**注释要求**：提到的函数/字段/路径必须 `grep` 确认存在；**数值必须带校准依据**（「半衰期 0.35h（血中 2~3 分钟）」）；禁止写实例名。

## 四、数值审查三问

1. 有校准依据吗？（文献 / 实测 / 拍脑袋）
2. 所有加法项叠满的上限在哪？有没有封顶？
3. 两条独立机制是否各自设了同一个上限？

答不了 → 标「待校准」写进 `共享/踩坑与未解问题.md`。

## 五、函数

| 规则 | 限值 |
| :--- | :--- |
| 长度 | ≤ 20 行 |
| 代码块 | `if`/`for` 内 ≤ 3 行 |
| 参数 | ≤ 3 个，超出封装 DTO |
| 抽象层级 | 所有语句同一层 |
| 副作用 | 要么「做事」（改状态），要么「回答」（返回），**不可同时** |
| 输出参数 | 禁止；返回值优先 |

**存量例外**：`面板.mjs` 等大文件是已知债 —— 新增函数必须 ≤20 行；改大文件优先提取，不整体重写。

## 六、模块 / 类

| 规则 | 判据 |
| :--- | :--- |
| 高内聚 | 模块内函数应共享同一批数据 |
| 开放-封闭 | 用注册表/策略表扩展，不新增 `if` 分支 |
| 依赖注入 | 参数注入，禁止函数内 `new` 具体依赖（工厂除外） |

**名字承诺必须兑现**：

| 名字 | 必须 |
| :--- | :--- |
| `读()` | 只读，不写盘 |
| `--看` / `--print` | 零写入 |
| `--dry` | 零写入（含不建目录） |
| `结算X` | 幂等 |

**幂等**：结算/推进/归档类必须重复调用结果一致（记 `上次结算时刻` / `已用` / 去重 id）。

**精炼**：一行能说清就一行（`export const 价 = (名) => ...`）；禁止假抽象；卫语句提前返回消嵌套。

## 七、错误处理

| 场景 | 规则 |
| :--- | :--- |
| 异常 | 必须带上下文 + 保留原异常（`new Error(msg, { cause: e })`） |
| 主流程 | 保持无 `try` 直线，错误处理放边界 |
| 空 `catch` 旁路（审计/指标） | ✅ 但**必须注释「为什么可以吞」** |
| 空 `catch` 主流程/结算/调度 | ❌ 必须 `console.error` 或写日志文件 |
| 下游 `stdio:'ignore'` / `process.exit` | ❌ 必须写日志文件（stdout 会丢） |
| 返回值 | 优先空集合/空对象/抛异常；返回 `null` 必须注释「调用方必须判空」 |
| CLI 退出码 | 语义必须与调度器一致 —— 心跳把非 0 当失败，就不能用非 0 表达「正常但没活干」 |

**「失败不拦主流程，但必须留痕」**。

## 八、`ENTRY_GUARD`（强制）

```js
const 是入口 = (() => {
  try { return !!process.argv[1] && path.resolve(process.argv[1]) === fileURLToPath(import.meta.url) }
  catch { return false }
})()
if (是入口) { /* 主流程 */ }
```

契约检查已钉。**原因**：冒烟测试逐个 `import`，无守卫会真跑主流程（曾真戳人 / 写盘 538 次）。

## 九、第三方封装（适配器边界）

第三方（DB / HTTP / 工具库）**只能出现在 `共享/工具/接口/`**。

封装三要求：① 统一返回 `{ ok, err, fatal }`；② 抹掉实现细节；③ 内部处理已知怪癖。

**业务层禁止**：`fetch(` / `execFileSync('curl'` / `new DatabaseSync(` / 第三方特有字段（`retcode`、`data.message`）。

检查：
```bash
grep -rn "fetch(\|execFileSync('curl'" 共享/工具/核心 共享/工具/判据 共享/工具/领域
```

## 十、分层与依赖

**依赖方向（唯一合法）**：`出口/ → 接口/ → 领域/ → 判据/ → 核心/`

| 层 | 目录 | 禁止 |
| :--- | :--- | :--- |
| L1 实体 | `核心/` | import 任何上层 |
| L1.5 判据 | `判据/` | 写业务盘 |
| L2 用例 | `领域/` | import 接口/出口；`_总线` 不写业务盘 |
| L3 适配器 | `接口/` | 被内层 import |
| L4 外层 | `出口/` | —— |

**跨层必须用 DTO**（普通对象/基本类型），禁止传实体对象。

**外圈可替换**：代理、TTS、视频理解、模型上游、存储 —— 换实现只改配置不改代码。

**架构债（禁止扩大）**：`面板.mjs` 过大 / 接口网关与接口中转重叠 / 体力封顶双轨 / 存量扁平目录。

## 十一、测试

**FIRST**：Fast（单元全量 <60s）、Independent（自建沙盒自清理）、Repeatable（时间/随机可注入）、Self-Validating、Timely。

**金字塔**：单元 ≥70%（实体+用例，无外部服务）、集成适度（适配器）、E2E ≤10%（关键路径）。

**修 bug 必补测试**（没补 = 没修完）。

**命名**：`methodName_scenario_expectedBehavior` 或中文描述式（「Z4 目录卫生 的归档正则认得 早间简报」）；断言失败信息必须自解释。

**隔离四条 + 三条**：
1. 不共享状态（`mkdtempSync` + `finally` 清理）
2. 不依赖执行顺序
3. 不碰真数据（写盘重定向沙盒）
4. 不留脏文件（`try/finally`）
5. **沙盒目录必须自己 `mkdirSync`**
6. **依赖外部服务的测试必须先探端口，不可用就整份 `exit 0` 跳过**
7. **import 插件的测试必须 `QUIET_NOTE=1`**

**断言**：强断言优先（禁 `assert.ok(结果)`）；一条测试一个行为；**禁止钉死字面量**（钉结构/语义，不钉拼法）；哈希断言只覆盖协议 schema。

**测试目录镜像生产目录**（见系统规矩 §1.3）；新模块无镜像测试 → 契约红灯。

---

## 十二、配置与依赖

**优先级**：显式参数 > 环境变量 > 配置文件 > 代码默认。配置位置清单见系统规矩 §4.4（新增必须登记）。

**环境变量命名**：`QQ_*`（路径）/ `DSH_*`（DSH 参数）/ `FISH_*`（沙盒开关）/ `<简写>_MEM`·`<简写>_BASE`（单模块沙盒）/ `BOT_ROLE` / `*_TOKEN` / `*_PORT`。

**不使用 DI 框架**：ESM 静态 `import` 已够；「可换实现」靠配置 + 运行时读。判据：**换实现只改一个 JSON 就不需要 DI**。

**版本锁定**：确切版本，禁 `^`/`~`/`latest`，禁 `npm install` 不带 `--save-exact`。
**脚本零第三方依赖**（全用 Node 内置）。
**准依赖探活**用 `/proc/net/tcp` 或 `systemctl is-active`，**不用 `curl`**。

## 十三、新建代码流程

**六步前置（用户确认后再编码）**：
1. 实体是什么（数据档 + 判定规则）
2. 用例是什么（一句话 + 输入/输出）
3. 属于哪一层
4. **依赖检查**：依赖谁 / 谁依赖它 / 有无环 / 判据是否重复 / 写方是否唯一 / 有无硬编码
5. 怎么测（沙盒变量 + 镜像测试路径）
6. 配置放哪（是否需新增登记）

**从内向外**：`核心 → 判据 → 领域 → 接口 → 出口`，每层先写测试。

**必须建模块目录**：`<层>/<模块名>/index.mjs`（禁顶层平铺）。对外只暴露 `index.mjs`。

**必过项**：`node --check` → 自测通过 → 依赖检查通过 → 契约不新增红 → 静态检查 0 崩引用 →（进模板）自检 6/6。

**同步产出**：文件头注释（为什么/用法/沙盒变量）+ `共享/变更.md` 一行 + 镜像测试 +（若需）配置登记。

---

## 十四、维护与重构

**改前四步**：读代码行为 → 实测 → 识别层级（依赖检查）→ **拿改前基线**（跑门禁/测试）。

**单次上限**：

| 改动 | 上限 |
| :--- | :--- |
| 修 bug | 1~3 文件 |
| 提取函数 | 1 文件 |
| 收口判据 | 3~5 文件，分两步 |
| 改数据档结构 | 迁移脚本 + 全部读方 |
| 目录迁移 | 一次一个模块 |
| `面板.mjs` | 禁止整体重写 |

**重构与改行为分开提交。**

**坏味道清单**：长函数 / 大类 / 重复代码 / 特性依恋 / 数据泥团 / **死字段**（只写无读或只读无写）/ **注释骗人** / **空 catch** / **双轨上限** / **假开关** / **平铺未分层** / **测试未镜像**。

**测试守护**：改前补测试 → 改后必过 → 行为不变用 `diff before/after`。

**文档同步**：目录→系统规矩；门禁→系统规矩；代码规范→本文件；配置→系统规矩 §4.4；**任何实质改动→`共享/变更.md`**。

**技术债登记** `共享/踩坑与未解问题.md`：现象 / 根因 / 影响 / 临时规避 / 修复方向 / 日期+责任方。存量债不得扩大；新增债当场登记并标 `// TODO(日期, 责任方): ...`。

## 十五、AI 行为准则

**先分析后行动**：现状核实（读代码+实测，列已验证事实）→ 层与依赖分析（依赖检查通过？）→ 改动方案（最小可行 + 影响范围 + 验证方式）。**用户确认后再写代码。**

**禁止**：凭文件名/函数名/注释推断行为；凭旧批次号推断现状；不读配置现值就用代码 fallback。

**解释决策**：违反/遵守了哪条 + 改进理由 + 影响范围 + 验证方式。

**渐进式改进**：禁止一次性大重写（含目录迁移）；每步保持可发布。

**自我验证**：必须给可复制命令 + **带具体数字的预期**（如「契约检查：0 项不对」）。**没实际跑 = 没完成**；无法验证必须说明原因并给用户可执行命令。

**安全默认预防**：命令注入（`execFileSync(cmd, [args])`）/ 路径穿越（`resolve` 后校验前缀）/ 凭据泄露（日志禁打 token）/ 鉴权绕过（出站必经 `发送口` 白名单）/ 竞态（`改档`/`saveState` + pid+random）/ N+1 进程 / 无界全表扫描（用增量索引）/ 记忆体内累积（定期裁剪）。

**拒绝脏代码**（说清违反哪条 + 给等价值合规方案 + 说明代价）：

| 要求 | 合规替代 |
| :--- | :--- |
| 硬编码密钥 | 配置 / 环境变量 |
| 巨型函数（>100 行） | 拆小函数 |
| 复制粘贴 3 次以上 | 提取单一真源 |
| 业务直连第三方 | 加适配器 |
| 空 catch 吞主流程 | 至少 `console.error` |
| 硬编码实例名/路径 | 占位符 / 环境变量 |
| 顶层平铺新 `.mjs` | 建 `<层>/<模块名>/index.mjs` |
| 新模块不建目录 | 建模块目录 |
| 测试平铺根层 | 建镜像子目录 |
| 新模块无测试 | 补镜像测试 |
| 跨层反向 import | 抽接口 / 下沉 |
| 绕过契约红线 | 修到绿再发 |
| 删/弱化测试 | 修实现或修断言 |

**违规处置**：P0（凭据/白名单/门禁）立即回滚；P1（反向依赖/顶层平铺）当轮修正不许合并；P2（空 catch/临时名/无沙盒/无镜像测试）当轮修正或登记；P3（命名/注释）可登记。

## 十六、文档文字

规范的读者是要照着做事的人，不是来考古的。

| 规则 | 做法 |
| :--- | :--- |
| 只写现状 | 不写沿革、批次号、「以前是…后来改成…」。过程进 `共享/变更.md`，淘汰内容进 `_归档/` |
| 标题不带废括注 | 删「（现代模块化设计）」「（新版）」「（推荐）」；只有「可选 / 强制 / 阶段」这类改变行为的限定语才留 |
| 一条规矩写一处 | 其它文档只写 `见 <文件> §x`，不复制正文；复制两份必然先烂一份 |
| 示例可执行 | 命令带全路径、参数写全；示例里的实例名、端口一律用占位符 |
| 数字带口径 | 阈值、实测值注明来源日期（如「2026-11-25 实测」）；没有口径就不写具体数 |
| 术语统一 | 模块名、文件名、键名用反引号；同一个东西全文只用一个称呼 |
| 少用表格 | 只有对比、清单、映射才用表；一句话能说清就写句子 |
| 长度可控 | 单文件超过 300 行先考虑拆分；每节标题要能回答「读完这节我要做什么」 |
