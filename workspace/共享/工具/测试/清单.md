### ✅ 已修（批次385）· ★ P1 · 饥饿.吃() 的「加」参数被吞掉 —— 饱腹一点都不涨

**位置**：`饥饿.mjs` 的 `吃()`，表里查不到那个名字时的分支。

```js
} else {
  // 表里没有：把「加」当作饱腹点数（1 点 = 20 千卡），临时加当作毫升
  kcal = Math.max(0, Number(加) || 0) * 20
  if (kcal) 饱渴.喝(0, now)      // ← 喝 0 毫升：只固化衰减，一个卡都没加
  if (补 = Math.max(0, Number(临时加) || 0)) 饱渴.喝(补, now)
}
```

`kcal` 算出来了，但**从未写进饱渴**。`饱渴.喝(0)` 只把衰减固化一次，卡/胃都不动。
「临时加」（毫升）那条是有效的 —— 所以只有「加」这条路是空的。

**实测**（t379 的 E2）：

```
饥饿.吃({ 名: '不存在的自制饭', 加: 20 })   → 返回 kcal: 400
饱渴.读().卡：500 → 500（应该 900）
```

**影响面**：不是死代码。`活动.mjs:148` 真的在调：

```js
if (kind === "吃") {
  const h = 饥饿.读()
  if (饥饿.想吃意向(h.饱腹, 饥饿.距上次分钟(h)) >= 0.3) {
    饥饿.吃({ 名: `在${地点}吃了一顿`, 加: 42, 价: 0, 类别: "吃" })
  }
}
```

即「她人在吃饭的地方（餐厅/咖啡店），随机活动跑到吃」这条路：**840 千卡凭空消失，
饱腹不涨、饱渴账不记，只有 `饥饿.json` 的顿数和「最后吃了」变了。**
而且 `类别='吃'` + kcal 840 ≥ 400 → 顿数还会 +1，等于「记了一顿但没吃」。

**线上现状**：还没被触发过。`饥饿.json` 的 `最后吃了` 是「一顿正经饭」（走 `吃饭.mjs` 正路），
`饱渴.json` 的 93 条账里 0 条「吃了一顿」。属于**潜伏 bug**。

**修法建议**（待点头）：把 `饱渴.喝(0, now)` 换成 `饱渴.补液(临时加, kcal, 0, now)` ——
它本来就是「水 + 卡 + 血糖一起进、但不走口粮表」的入口，为这种场景写的。

### ✅ 已修（批次385）· ★ P2 · `consumptionSucceeded` 的两处判据漏洞（t393 抓到）

**一、`吃了 面包`（带空格）不被认成吃上了**

```js
consumptionSucceeded: /^(?:坐下来吃\S|吃了\S|喝(?!不上|不了)\S|...)/     // 没有 \s*
purchaseSucceeded:    /^(?:买了\s*\S|点了外卖\s+\S|...)/                 // 有 \s*
```

两处口径不一致：买东西允许空格，吃东西不允许。实际调用方（`t353` 的样例）
产出的都是无空格格式（`坐下来吃糖，大概 8 分钟`），所以线上没暴露；
但只要哪次输出带个空格，就会被判成「没吃上」。

**二、`喝不下了` 被认成「喝成功」**

```js
/喝(?!不上|不了)\S/    // 负向断言只写了 不上 / 不了，漏了 不下
```

`喝不下了` → `喝` 后面是 `不下`，两个负向断言都不命中 → 匹配成功。
后果：明明没喝到水，动作判定成功，20 分钟冷却也跟着记上，于是她 20 分钟内不会再试。

- `自主状态.起()` 的 `since` 用 `Number(字段.since) || Date.now()`：**负数会原样写进去**
  （只有 0/空串/null 才回落到 now）。谁传了负时间戳，面板算「已经多久」会算出一个巨大的数。
- `写日记.mjs` / `自我巡检.mjs` **把 MEM 硬编码成 `{{BOT_ROOT}}/记忆`**，不认任何 env ——
  这两个模块没法沙箱测试，也没法在二号机上跑。要动它们得先改成 env 兜底。

- `账本.某天(记录, '')` 或传 `null` 时，`startsWith('')` 恒真 → **返回的是全部记录的合计，
  不是 0**。调用方要保证日期非空；现在唯一的调用方都是传 `bjNow().slice(0,10)`，走不到。

- `slotRelationBond` 对 `ctx.memDir` **没有防御**：缺了直接抛 `TypeError`。线上
  `extraHintOf` 每次都传，所以不触发。
- `营业中` 的 `休` 如果是字符串（`'123'`），`'123'.includes(3)` 会按子串命中 → 误判休息。
  真实地图 20 个地点的 `休` 全是数组，不受影响。
- `到了()` 的判据是 `arriveAt > now`，所以**在途缺 `arriveAt` 时会被当成「已到」**
  （`NaN > now` 为 false）。脏数据隐患，现在没有任何地方写这种在途。
