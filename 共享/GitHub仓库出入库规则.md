# GitHub 仓库出入库规则（通用模板仓版）

> 给协作 Agent 与新会话使用的出入库规范。
> 核心原则：**仓库只存脱敏后的通用模板；入库必脱敏并过全门禁，出库必差异审计、先备份、还原实例规则后再推实例。**

---

## 一、三层边界

1. **协作 Git 仓库（`azlanders/our-work`）**：只存放通用模板、通用插件源码（`dsh/vendor/*`）、`patches/`、`tests/`、脚本与脱敏台账（`共享/变更.md`）。**禁止入库**：`instances/*.env`、运行态记忆/日记/数据库（`*.db`）、大体积二进制媒体、`node_modules/`、`__pycache__/`、第三方大包（`three/*.js`）。
2. **模板库（`bot-template`）**：在服务端保存与仓库一致的通用骨架，同时持有真实的 `instances/*.env`、真实 UIN 脱敏映射表（`clean-persona.py`）和真实残留扫描正则（`自检.sh`）。
3. **实例运行区（`{{BOT_ROOT}}` / `{{DSH_ROOT}}`）**：通过 `推给所有实例.sh` 或显式 `dsh` 同步流程接收模板改动；实例独有数据（`SOUL.md`、`记忆/`、`共享/变更.md` 等）永不入通用模板。

---

## 二、入库规则（服务端模板 / 优化波次 → Git 仓库）

1. **源头控制**：只从已清理的模板目录或经过 diff 审查的重构补丁包合入 Git 仓库，不直接从实例运行区打包。
2. **脱敏要求**：仓库内禁止出现真实服务器 IP、真实 QQ 号、特定实例名与实例绝对路径；统一使用 `{{BOT_NAME}}`、`{{BOT_ROOT}}`、`{{DSH_ROOT}}`、`{{QQ_HOME}}`、`{{SELF_UIN}}` 或脱敏占位示例（如 `脱敏示例号`、`10.0.0.2`）。
3. **自检门禁（必过）**：在 Linux 临时目录对仓库完整副本执行：
   - `bash 自检.sh`（**6/6** 全部 `ok`：实例残留扫描、占位符核对、特殊字符临时安装 + `.mjs` 语法、桥/服务/dsh 渲染、压缩切点回归、`test-tpl-engine.py` + `test-mnemonic.mjs`）
   - 测完清理临时目录。
4. **台账与推送**：
   - 将本次通用改动脱敏追加到 `共享/变更.md`；
   - `git status -s` 核查无误后 `git commit && git push origin main`，并用 `git ls-remote origin heads/main` 确认远端哈希一致。

---

## 三、出库规则（Git 仓库 → 服务端模板 → 指定实例）

1. **只读差异审计先行**：先比对 Git 仓库与服务端模板目录的差异，**严禁直接整包覆盖**。
   - **跳过**仅因导出脱敏产生的差异文件（如业务代码中把真实 UIN 替换成脱敏假号的只读历史 diff）。
2. **先备份**：覆写任何文件前，打包原模板文件、目标配置或运行数据到 `/root/bak2/<YYYYMMDD-主题>/`。
3. **精准回流 + 还原服务端规则**：
   - 仅合入本次实际变更/新增的文件；
   - 若改动涉及 `clean-persona.py`、`自检.sh`、`tests/test-tpl-engine.py`，必须在服务端还原真实 UIN 映射与残留扫描规则，防止假号回灌或漏扫。
4. **模板自检**：在服务端模板根目录执行 `bash 自检.sh`，必须 **6/6** 全绿。
5. **推向指定实例**：
   - 先执行 `bash 推给所有实例.sh instances/<target>.env --dry` 预览受影响文件，确认无误后再正式推送（脚本会自动备份原文件到 `/root/bak2/实例-*.tar.gz`）；
   - 若改动涉及 `dsh/vendor/*` 或 `bridge/cordis.patch.yml.tpl`，同步到对应实例的 `profiles/web/` 并重启受影响服务（如 bot 主服务 / 网关服务），验证健康端口。
6. **实例门禁与台账**：
   - 实跑实例侧 `node 共享/工具/契约检查.mjs`（0 错）与 `QUIET_NOTE=1 node 共享/工具/自检.mjs`（0 错）；
   - 在目标实例的 `共享/变更.md` 追加本次回流记录（改了什么、为什么、影响范围、实测数字、备份路径）。

---

## 四、双向防呆提醒

- 服务端直接修改通用插件、停用/归档插件或更新 `cordis.patch.yml.tpl` / `package.json.tpl` 后，需及时反向同步回 Git 仓库，保持两边模板真源一致，防止下次出库回退。
